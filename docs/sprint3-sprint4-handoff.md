## What was implemented in this turn

### Sprint 3 — T18 Internship Log

- Added per-daily-log review fields (`reviewStatus`, `reviewComment`, `reviewedById`, `reviewedAt`) and migration `backend/prisma/migrations/20261008160000_internship_log_review/`.
- Added `PATCH /api/internship/logs/:id/review` in `backend/src/routes/career.routes.ts` and `backend/src/controllers/career.controller.ts`. Lecturer access is limited to their advisees, company access to its own interns, and staff/admin access is allowed. Students cannot review. Requesting changes requires a comment. The student receives an in-app notification after review.
- Added review status/comment and approve/request-changes controls in `src/components/internship/InternDetailView.tsx`; students see the status/comment in `src/components/internship/InternshipDiary.tsx`. Mapping and API client were updated in `src/pages/InternTracking.tsx`, `src/components/internship/types.ts`, and `src/lib/api.ts`.
- Added a 48-hour inactivity reminder for `in_progress` internship records in `backend/src/services/internship-reminder.service.ts`, started/stopped from `backend/src/server.ts`. It uses log submission time and a claimed `lastLogReminderAt` to avoid repeated notifications until a new log is submitted. Migration: `backend/prisma/migrations/20261008162000_internship_log_reminder/`.
- Tightened daily-log hours validation to 1–16 in `backend/src/schemas/career.schema.ts`.

The daily diary form (date, hours, work, learnings, challenges) was **already present** in `src/components/internship/InternshipDiary.tsx`; it was not reimplemented. Per-log file attachments and editing a log after “changes requested” were **not** implemented. The audit treats general internship documents as satisfying its attachment DoD, but confirm whether a per-entry attachment is now required.

### Sprint 3 — T20 Document Automation

- Added `IssuedDocument` with auto-incrementing ID, random verification token, issue timestamp, and revocation field. Reference format: `SHOWPRO-YYYY-000001`. Migration: `backend/prisma/migrations/20261008161000_issued_document/`.
- Transcript, internship certificate, and cooperation-summary PDFs now include the reference and an embedded QR image generated by `qrcode`; see `backend/src/services/pdf.service.ts` and `backend/src/controllers/documents.controller.ts`.
- Added public `GET /api/documents/verify/:token` and frontend `/verify/:token` (`src/pages/VerifyDocument.tsx`, `src/App.tsx`). Public response contains only reference, type, issue date, and validity—not student identity or grades. Also added an access-policy check to internship-certificate download.
- **Important limitation:** the QR confirms that the reference exists and whether it is revoked; it does **not** cryptographically prove the PDF content is unmodified. The verification page says this explicitly. `FRONTEND_URL` must be the real frontend origin before issuing production PDFs, because that URL is embedded in QR codes.
